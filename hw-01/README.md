# Описание поднимаемого стенда
## Что это за стенд
 
Стенд для показа продукта клиентам в Yandex Cloud. Состоит из сети ivanov-01-net с подсетями в зонах ru-central1-a (10.11.1.0/24) и ru-central1-b (10.11.2.0/24), двух веб-серверов ivanov-01-web-1 и ivanov-01-web-2 в разных зонах, сервера приложения ivanov-01-app-1 без публичного адреса, NAT-шлюза ivanov-01-nat и балансировщика ivanov-01-lb. Балансировщик принимает запросы на порт 80 и передаёт их на порт 8003 веб-серверов. Если один веб-сервер откажет, стенд продолжит работать. Машины настраиваются сами через cloud-init. Все ресурсы помечаются метками env=lab и owner=ivanov-01.
 
Перед запуском нужны Yandex CLI с настроенным профилем, jq, curl, ssh, envsubst и SSH-ключ ~/.ssh/id_ed25519.pub.
 
## Как поднять и снести стенд
 
Все команды выполняются из корня репозитория.
 
Поднять стенд (около 2,5 минуты):
`./hw-01/create.sh`
 
Проверить стенд (код 0 — всё в порядке, 1 — есть ошибка):
`./hw-01/check.sh`
 
Снести стенд (около 2,5 минуты):
`./hw-01/destroy.sh`
 
В конце работы create.sh выводит адрес стенда. Перед показом подождите 1–2 минуты, пока машины настроятся, и убедитесь, что check.sh вернул 0. create.sh можно запускать повторно: уже созданные ресурсы он пропускает. После показа стенд нужно снести, иначе он продолжит тарифицироваться.
 
## Параметры create.sh
 
Параметры передаются позиционными аргументами. Если параметр не передан, используется значение варианта. Чтобы задать параметр, нужно передать и все параметры перед ним.
 
1. PREFIX — префикс имён ресурсов, по умолчанию ivanov-01
2. ZONE_A — зона A, по умолчанию ru-central1-a
3. ZONE_B — зона B, по умолчанию ru-central1-b
4. CIDR_A — подсеть A, по умолчанию 10.11.1.0/24
5. CIDR_B — подсеть B, по умолчанию 10.11.2.0/24
6. APP_PORT — порт nginx, по умолчанию 8003
7. GREETING — слово на странице, по умолчанию labwork
8. VM_COUNT — число веб-серверов, по умолчанию 2
9. BOOT_SIZE — размер загрузочного диска в ГБ, по умолчанию 15
10. IMAGE_FAMILY — образ машин, по умолчанию ubuntu-2404-lts
11. ENV_NAME — имя окружения, по умолчанию lab

Пример запуска с тремя веб-серверами:
`./hw-01/create.sh ivanov-01 ru-central1-a ru-central1-b 10.11.1.0/24 10.11.2.0/24 8003 labwork 3`
 
check.sh принимает PREFIX и APP_PORT, destroy.sh принимает PREFIX. Если при создании стенда префикс или порт менялись, передайте этим сценариям те же значения.
 
## Что делать, если check.sh вернул ошибку
 
Проверка 1: «балансировщик недоступен». Стенд не поднят или поднят с другим префиксом. Запустите create.sh или передайте check.sh правильный префикс.
 
Проверка 1: балансировщик отвечает не кодом 200. Если стенд только что поднят, подождите 1–2 минуты и повторите проверку.
 
Проверка 2: «ответила только одна машина». Найдите неисправную машину командой `yc compute instance list`. Если она остановлена, запустите её командой `yc compute instance start <имя>`. Если машина работает, зайдите на неё по SSH и запустите nginx: `sudo systemctl start nginx`.
 
Проверка 3: «не удалось получить адреса». Нет машины web-1 или app-1. Запустите create.sh, он создаст недостающие машины.
 
Проверка 3: «сервер приложения недоступен». Проверьте статус cloud-init на сервере приложения через web-1:
`ssh -J student@<адрес web-1> student@<внутренний адрес app-1> "cloud-init status"`
Если статус error, значит, у машины не было выхода в интернет. Проверьте, что к подсети ivanov-01-subnet-a привязана таблица маршрутизации ivanov-01-rt. Затем удалите ivanov-01-app-1 и снова запустите create.sh.
 
Если ничего не помогло, снесите стенд и поднимите его заново: destroy.sh, затем create.sh.
