# Дневник расхождений
1. Нет памяти о созданном: create.sh ищет ресурсы по именам, destroy.sh по метке owner, ресурсы без метки или переименованные не видны.
2. Проверяется только имя ресурса, а не параметры: изменённые подсеть, порт или размер диска на поднятом стенде не применяются.
3. Целевая группа не обновляется: при изменении числа веб-серверов новые машины не попадают в балансировку, лишние не удаляются.
4. Нет предварительного просмотра изменений перед запуском create.sh и destroy.sh.
5. Идемпотентность написана вручную: 10 проверок существования занимают половину строк кода create.sh.
6. Порядок создания и удаления держится только на порядке строк в сценариях.
7. При сбое посередине create.sh остаётся частично созданный стенд, который продолжает тарифицироваться.
8. Не учитываются переменные окружения: приоритет параметров только «аргумент → значение по умолчанию».
9. Параметры только позиционные: чтобы изменить восьмой, нужно передать все семь предыдущих.
10. Нестандартные префикс и порт нужно помнить и передавать в check.sh и destroy.sh отдельно.
11. create.sh не ждёт готовности машин: check.sh сразу после него может не пройти.
12. Третья проверка check.sh идёт только через web-1: при его отказе сервер приложения считается недоступным.
13. SSH в check.sh интерактивен: на новом стенде ssh спрашивает подтверждение ключа хоста.
14. Сценарии запускаются только из корня репозитория из-за относительного пути к шаблону.
15. SSH-ключ зашит в сценарий: используется только ~/.ssh/id_ed25519.pub.
16. Адрес балансировщика меняется при каждом подъёме стенда.
17. Прерываемые машины могут быть остановлены облаком в любой момент и сами не запускаются.
18. Загрузочные диски не получают меток, их отсутствие после уборки приходится проверять вручную.
